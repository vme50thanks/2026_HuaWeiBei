# D题求解前计算规则核验与航段基础数据

本报告完成三项准备工作：核验附件中的能耗公式，制定可执行的时间及资源占用基准，生成16个运输节点之间的240条有向航段和三种机型的720条航段飞行时间记录。未计算最大安全载荷，未进行货箱优化或联合调度。

结论：几何与飞行时间数据已生成并校验；原文中的能耗分项定义仍不完整，不能称为已获得官方完整能耗模型。时间口径已形成基准版本，其中原文没有规定的部分明确标为工作假设，需要用户核验。

## 1 能耗公式核验

### 1.1 核验范围和证据

读取题目DOCX的正文与Office数学公式结构，核对其中72个数学对象（含行内符号，不代表72个独立公式），检查其他XML部件中的数学对象、嵌入对象及正文图片；原文图片为地形节点图。检查运输与中继参数表及单元格批注；未发现能耗分项的补充批注或嵌入公式文件。证据摘录见 `appendix2_evidence.txt`，按正文XML中的段落顺序编号，非Word页码。

已确认原文附录2给出：

\[
L_g(q)=L_g^0-(L_g^0-L_g^F)\left(\frac{q}{Q_g}\right)^{3/2},\quad 0\le q\le Q_g.
\]

\[
t_{gij}=\frac{h^+_{ij}}{v_g^\uparrow}+\frac{d_{ij}}{v_g^c}+\frac{h^-_{ij}}{v_g^\downarrow}.
\]

\[
E_{gij}(q)=E^{\mathrm{hor}}_{gij}(q)+E^{\mathrm{up}}_{gij}(q),\qquad
\sum_{(i,j)\in p}E_{gij}(q_{pij})\le(1-\rho_g)E_g^{\mathrm{use}}.
\]

全文给出了两种能耗分项的名称，但未给出本地文件中可核实的展开式。特别是，不能把“航程如何折算电量”或“0.72效率如何代入”自行写成原文规定。

原文明确：下降效率取0表示不单独计算下降附加能耗；各航段用该段剩余货物质量，不能全程沿用起飞货量；SOC按可用能量核算；初始及再次投入任务前SOC均为100%。

### 1.2 可采用但尚待核验的能耗补全方案

若确认“标准航程对应消耗整组可用能量”，可采用：

\[
E^{\mathrm{hor}}_{gij}(q)=E_g^{\mathrm{use}}\frac{d_{ij}}{L_g(q)}.
\]

若确认“爬升能耗效率”是电能转化为重力势能的效率，可采用：

\[
E^{\mathrm{up}}_{gij}(q)=\frac{(m_g^0+q)g_0h^+_{ij}}{\eta_g^\uparrow\cdot3.6\times10^6},\qquad g_0=9.80665\ \mathrm{m/s^2}.
\]

这里质量是含电池空载总质量加货物质量，焦耳换算为kWh需除以3.6×10^6。效率放在分母是基于上述物理解释，**需要用户核验**。若标准航程本身已经扣除安全余量，则第一条候选式的标定还需调整，不能再次机械扣减。未将这两条候选式写入航段结果，也未据此计算能耗或载荷。

中继水平能耗可按原文文字写为 `巡航功率(kW)×巡航秒数/3600`；有效服务能耗为 `(悬停功率+通信附加功率)×服务秒数/3600`。中继爬升能耗依赖上述待核验关系，质量取23.5kg。30秒建链阶段是否计入通信功率、运输交接阶段是否另计悬停能耗，没有完整明确的分项规则，均列为需要用户核验，不能视为零能耗的已证事实。

### 1.3 已明确的SOC和充电公式

满电出发时，`SOC_return = 1 - E_sortie / E_use`，须满足 `SOC_return >= rho`。SOC内部统一用0—1，输出百分数时再乘100。

\[
t_{\mathrm{chg}}(s)=
\begin{cases}
T_{\mathrm{full}}[0.65(0.90-s)/0.90+0.35],&0\le s<0.90,\\
T_{\mathrm{full}}\,0.35(1-s)/0.10,&0.90\le s\le1.
\end{cases}
\]

该公式在0.90处连续，且 `t_chg(0)=T_full`、`t_chg(0.9)=0.35T_full`、`t_chg(1)=0`。不得用“缺电比例×完全充电时间”替代两阶段公式。A/B/C运输电池的完全充电时间分别为1800/2400/3000秒，中继组件为1800秒。

## 2 时间与资源占用统一基准

完整19条规则及其来源、状态见 `time_rules.csv` 和 `time_rules.json`。以下为基准实现口径；假设不等于官方解释。

### 2.1 运输时间线

`架次开始s_p → 固定准备 → 逐箱装载 → 起飞 → 各航段飞行 → 每站交接 → 返回O01落地f_p`

- 将“开始时刻”定义为准备开始，需要用户核验；另保留 `takeoff_time`，避免与起飞混用。
- 起飞时刻 `s_p + 300 + 30N_p`，三类机型准备及每箱装载参数相同。
- 到达服务区后，本次交接时长为 `b_g + c_g n_pi`。A/B为 `150+30n_pi` 秒；C为 `180+36n_pi` 秒。
- 基准下，该次访问全部货箱统一在交接结束时标为完成交付。这是保守工作假设，需要用户核验；它可能使原本可顺序提前交付的医疗箱被判迟到。
- 如采用顺序交付，需另外定义箱序，按 `到达+基础交接+k×每箱时间` 记录第k箱；此替代口径与基准不得混用，应比较对硬时限的影响。
- 从交接结束时起，以更新后的载荷执行下一航段；不允许交接尚未完成便起飞。

### 2.2 资源占用

资源占用按半开区间表示，同一资源前一任务释放时可以开始下一任务。

| 资源 | 基准占用和恢复规则 | 依据与状态 |
|---|---|---|
| 运输无人机 | 占用 `[s_p,f_p)`；下一次准备不得早于f_p | 附件无单独运输周转常数；暂不另加，需核验 |
| 运输电池 | 准备开始即预留；飞行结束后充电，`f_p+t_chg` 才能再次分配 | 满电复用为题目规定；预留、立即拆卸为工作假设 |
| 中继无人机 | `准备180秒→外飞→建链30秒→服务→返航→周转300秒`；占用到 `f_r+300` | 时长来自附件；周转放在返航后需核验 |
| 中继能源组件 | 准备开始预留；返航后立即充电，与机体周转可并行 | 独立能源资源为题目规定；阶段衔接需核验 |

额外拆装时长基准取0，不凭空添加实测参数，需要用户核验。不同电池/组件可并行充电；未给出充电器数量，不额外设置单充电器瓶颈。附件也未提供共享准备工位数，暂不设单工位排队，但每次准备均占用其无人机和被分配能源。

库存基准：运输机A/B/C为4/2/2架，电池为6/4/4组；中继机2架、组件6组。电池总数已包含初始机载使用，不能再加8组。

### 2.3 通信与最终完成时刻

中继从建链完成后才能提供服务，外飞、建链及返航不算有效中继保障。运输通信检查覆盖从起飞爬升到返航落地的各飞行及交接阶段。

第二问完成时间取运输机最终返航时刻最大值；第三问还须包含中继机最终返航。题目未要求完成最终补电才算完成，因此最后一次任务后的周转和充电不加入上述指标，但若有后续架次仍必须影响资源再次可用时间。

第一问累计作业时间在本基准中定义为各架次准备、装载、飞行和交接之和，不含排队、补电；这是对“累计作业时间”的工作定义，需要用户核验。

## 3 航段基础数据

### 3.1 坐标、距离与像元定位

- GeoTIFF尺寸1309行×1486列，EPSG:4326，全部1,945,174个高程值有效；全图高程41.6891—1132.8561米。
- 原始GeoTIFF的RasterType为PixelIsPoint，首个样点中心为 `(109.0327777778°,23.2247222222°)`，像元间隔均约1/3600°。读取原始TIFF标签时，像元覆盖范围应向中心两侧各扩展半个像元。程序没有把样点中心错当左上角。
- PDF给出的NoData为−32767；TIFF本身没有GDAL NoData标签。本次显式按PDF值检查，未发现缺失像元。
- 使用WGS84局部线性米制坐标，中心为16节点包围盒中心 `(109.2262272°,23.0423605°)`。`x=(lon-lon0)×102490.51623859169`，`y=(lat-lat0)×110744.60150310313`，单位米；系数来自WGS84椭球在中心纬度的曲率半径。
- 水平距离取该局部平面中的直线长度。线性坐标变换使该路径在经纬度栅格中仍为直线，便于一致地确定经过的像元。这是明确的数值近似，并非把经纬度直接当作米，也不冒称UTM或精确大地线。
- 与零海拔WGS84地心坐标中的三维弦长交叉比较，最大相对差约0.02670%，最大绝对差约2.273米。弦长是独立核查量，不是精确测地距离；对本区域尺度该检查用于暴露单位、纬度缩放等错误。若后续方案接近硬时限或能量边界，应提高几何精度复核。

### 3.2 沿线最高高程及作业高度

采用全像元穿越算法：在所有栅格边界处分割线段，收集线段接触的像元；恰好沿边界或碰到角点时保守计入邻接像元。取其最高值加50米作为巡航海拔，不用稀疏采样近似最高点。

节点作业海拔使用节点表海拔：O01不加高度，服务区加30米。DEM只用于沿途地形和净空。两种来源同时保留，未擅自覆盖附件节点海拔；这一数据来源选择需要用户核验其是否符合后续官方澄清。

节点表海拔与所在DEM像元高程的最大绝对差为10.5629米，位于S009；O01差为−1.0255米。差异不自动视为错误，可能与采样、地表模型和源数据口径有关，原因未经验证。后续低空通信遮挡检查需特别处理节点表海拔与DSM的差别，不得将本次几何通过视为通信已可行。

对所有240条航段，按 `爬升=巡航海拔−起点作业海拔`、`下降=巡航海拔−终点作业海拔` 计算；本次无负值，未用截断为0掩盖不一致。

### 3.4 文件及字段说明

| 文件 | 内容 |
|---|---|
| `nodes.csv` | 节点位置、附件海拔、所在DEM像元高程、差值、作业海拔及局部平面坐标 |
| `legs.csv` | 240条有向航段的距离、最高地形、巡航高度、爬升下降、经过像元数及最高点位置 |
| `flight_times.csv` | 720条机型航段记录，分别给出爬升、巡航、下降和总飞行时间 |
| `time_rules.csv` / `time_rules.json` | 时间与资源规则，区分题目规定、假设和未决问题 |
| `audit.json` | 数值检查摘要、源文件SHA256、坐标参数、误差与限制 |
| `appendix2_evidence.txt` | 从本地DOCX结构提取的附录2证据，公式已转为可读线性形式 |
| `build_preflight.py` | 可复算脚本，仅读取原文件，将生成结果写入指定输出目录 |

字段后缀 `_m`、`_s`、`_deg` 分别表示米、秒和度；`dem_row_0`、`dem_col_0`及最高点行列号从0开始。`ground_table_m`来自节点表，`ground_dem_cell_m`为所在像元值，`operation_alt_m`为采用的作业海拔。`projection_vs_chord_relative_error`是有符号比例，转百分数需乘100。

航段主键为 `(from_id,to_id)`；飞行时间主键为 `(from_id,to_id,model_id)`。不生成自环，CSV保存未人为取整的浮点值，Excel可直接打开。任何四舍五入展示值均不得反写替代计算值。

这些航段覆盖固定运输节点；第三问可变中继悬停点尚未选定，因此不包含其航段。中继悬停高度可能高于沿线最高地形加50米，届时还需明确飞行剖面，不能直接套用固定运输节点的高度表。

## 4 如何继续与复算

现在可以使用几何和纯飞行时间数据搭建第一问的计算框架。涉及能量、最大安全载荷、返航SOC及电池恢复时间的正式结果，必须明确采用何种能耗补全假设；得到官方澄清后应优先替换。不能将本报告标注为“完整题意已获官方确认”。

脚本依赖Python、numpy、Pillow、openpyxl和lxml。在这些依赖可用的环境中执行：

```powershell
python build_preflight.py --source 'D:\研一\比赛\中文题目\D题' --out '.\recomputed'
```

脚本读取与自身同目录的 `time_rules.json` 并导出规则CSV；报告是人工整理的解释文档，不由脚本重新编写。`audit.json`记录本次源文件哈希，若源文件更新，应重新生成全部派生数据。本次没有改动D盘原始附件。

本材料用于建模准备与可复核分析；若用于正式竞赛，应按赛事规则使用AI辅助并如实说明假设与来源。
